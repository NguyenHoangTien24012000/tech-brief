Token exchange khi migrate sang expiring offline token giờ retry được trong 7 ngày Mới
  • Áp dụng khi app migrate token offline cũ (không hết hạn) sang expiring offline access token mà không có user session.
  • Nếu lỡ mất response hoặc chưa kịp lưu: gọi lại đúng request đó với token cũ + client credentials trong 7 ngày → Shopify trả lại đúng cặp access/refresh token như lần đầu, gia hạn access token nếu cần (refresh token thì không).
  • Hết khả năng khôi phục khi: quá 7 ngày, app đã refresh cặp token đó, hoặc store đã được cấp token mới (auth code / ID-token exchange).
  • Token cũ vẫn bị vô hiệu cho GraphQL Admin API sau khi migrate. Retry trả về invalid_subject_token thì phải lấy token mới qua ID-token exchange hoặc authorization code grant.
  • Không bắt buộc sửa code, luồng hiện tại vẫn chạy.
👉 Vì sao quan trọng: App public nào cũng sẽ phải migrate token offline cho hàng nghìn shop; retry giúp tránh bắt merchant mở lại app để cấp quyền.
✅ Nên làm: Trong job migrate token: lưu access token + refresh token + expiry trong cùng 1 lần ghi, thêm retry trong 7 ngày, xử lý nhánh invalid_subject_token, xoá token cũ sau khi thành công.

Chuyển subscription Billing API sang Shopify App Pricing không cần merchant approve lại Mới
  • Partner Dashboard có tool migrate: tạo App Pricing plan từ các manual plan hiện có, test trên development store, rồi chuyển các subscription đơn giản (không có usage charge) sang plan tương ứng chỉ bằng 1 click.
  • Case phức tạp (usage-based, điều chỉnh giá, private plan) dùng lệnh Shopify CLI: shopify app subscription-migrations — xem trạng thái từng store, lên lịch chuyển hàng loạt, huỷ lịch khi cần.
  • Subscription được chuyển vào đầu kỳ billing kế tiếp; merchant không phải approve charge lại.
  • App đang dùng App Pricing rồi thì không bị ảnh hưởng.
👉 Vì sao quan trọng: App có nhiều plan kèm usage fee (tính theo order) nhiều khả năng rơi vào nhóm phải dùng CLI thay vì migrate 1-click.
✅ Nên làm: Liệt kê các loại subscription app đang có (plan thường, usage-based, private) và thử migrate trên dev store trước khi mở rộng.

Toolchain JS nhanh hơn: Oxc React Compiler 10x, Vitest 5, Vite+ 1.0 Mới
  • 4 tháng sau khi VoidZero về Cloudflare: hơn 80 release, đóng hơn 1.200 issue; Vite, Vitest, Rolldown, Oxc vẫn open source và không khoá vendor.
  • Oxc React Compiler (viết lại bằng Rust) compile React nhanh gấp 10 lần bản Babel. Bật trong Vite bằng @vitejs/plugin-react@^6.1 + oxc-transform-react, rồi react({ compiler: true }).
  • Vitest 5 nhanh hơn Vitest 4 tới 50%; tsgolint ổn định, nhanh hơn ESLint tới 18 lần trên codebase lớn; Oxfmt nhanh hơn Prettier 7 lần.
  • Vite+ 1.0 gom cả toolchain với cấu hình mặc định hợp lý. Kèm Vinext 1.0: chạy app Next.js (App/Pages Router) trên Vite, deploy được lên Workers, Netlify, AWS Lambda.
👉 Vì sao quan trọng: Test/lint/build nhanh hơn rút ngắn vòng feedback cho cả người lẫn AI agent trên repo JS lớn.
✅ Nên làm: Thử Vitest 5 hoặc tsgolint trên 1 package của repo để đo thời gian so với hiện tại.

Sidekick gọi được app intent không cần tools — có thể làm deploy fail Breaking
  • Trước đây extension phải khai báo tools mới được Sidekick gợi ý. Giờ extension admin.app.intent.link / admin.app.intent.render chỉ khai báo intent cũng được Sidekick hiển thị ngay, áp dụng mọi store, không gắn API version.
  • Nếu app có extension chỉ có intent mà shopify.app.toml thiếu extensions_summary trong mục [sidekick], lần shopify app deploy tiếp theo sẽ FAIL validation.
👉 Vì sao quan trọng: Deploy của app có thể bị chặn bất ngờ nếu có extension intent-only.
✅ Nên làm: Grep các shopify.extension.toml tìm [[extensions.targeting.intents]] không có tools; nếu có thì thêm extensions_summary vào shopify.app.toml rồi deploy thử lên dev store.

Anthropic: GLM-5.3 và năng lực tấn công mạng lan rộng Đọc sâu
  • GLM-5.3 (Zhipu/Z.ai, open-weight) tự viết exploit end-to-end ở mức gần Claude Mythos Preview: 50/410 lần thành công trên ExploitBench (V8), Mythos là 56/410.

👉 Vì sao quan trọng: Công cụ tìm và khai thác lỗ hổng ngày càng rẻ → cần siết vá dependency và review bảo mật.

Vì sao Shopify bỏ React Native sau 6 năm Đọc sâu
  • 2020 Shopify chuyển cả 6 app sang React Native vì build Android lâu và muốn iOS/Android đồng nhất; 5 năm sau vẫn hài lòng.
  • Giờ AI viết code native (và backend) đủ tốt, còn RN thêm một lớp abstraction → quay lại native. App Shop được viết lại native chỉ trong 12 tuần.
  • Lịch sử lặp lại: Airbnb từng lên RN năm 2016 rồi bỏ sau 2 năm vì hiệu năng. Kotlin Multiplatform có thể hưởng lợi từ AI.
👉 Vì sao quan trọng: Ví dụ thực tế cho việc AI thay đổi các quyết định kiến trúc/stack.
