Gemini 4 Argon: output tới 1M token, đứng đầu DeepSWE với 77,9%, giá mở màn $2/$10 mỗi 1M token Mới

Google DeepMind công bố Gemini 4 Argon, model frontier mới chuyên cho các workflow dài nhiều bước: software engineering, công việc tri thức (pháp lý, tài chính) và phòng thủ an ninh mạng. Argon chưa mở rộng rãi. Đợt đầu chỉ dành cho nhóm cyber defender tin cậy trong chương trình Fairwind, sau đó mới tới khách trả tiền API và thuê bao Google AI Ultra. Bài trên HN được 965 điểm và 657 bình luận, cao nhất trong ngày.

Giá mở màn$2 / 1M input · $10 / 1M output; cached input rẻ hơn 95%
Giá sau khuyến mãi$4 / 1M input · $20 / 1M output
Output tối đa1M token (trước đây 64K)
DeepSWE v1.177,9%, state of the art cho SE đường dài
Truy cậpHiện chỉ có cyber defender (Fairwind). Tiếp theo là paid API + AI Ultra

Google đang dùng Argon nội bộ ra sao

  • Agent Argon migrate codebase C/C++ sang Rust, từ thư viện vài chục nghìn dòng như re2, libgav1 đến kernel Fuchsia Zircon hơn 800K dòng. Code được audit tự động lẫn thủ công trước khi lên production.
  • Với libgav1 (bộ giải mã video), agent thay 32K dòng SIMD bằng safe Rust mà compiler tự vectorize được, qua nhiều vòng thử nghiệm profile-guided. Kết quả nhanh gấp 2,7 lần bản Rust port, output giống hệt.
  • Agent phân tích telemetry profiling toàn bộ fleet rồi tự áp dụng tối ưu bộ nhớ, giải phóng hơn 300 TiB RAM. Google ước tính tổng tiết kiệm 500 TiB đến 1 PiB.

Benchmark ngoài coding

  • Dẫn đầu Vals Index (đo tác động kinh tế qua finance, coding, legal, tax). Đứng #1 AutomationBench của Zapier với 51,3%.
  • LVBench (hiểu video dài) đạt 91,7%. CWE-bench v1 (vá lỗ hổng) đồng hạng nhất với 68%.
  • Google sẽ cấp cho defender tin cậy một bản không có cyber guardrail. Wiz dùng Argon tìm ra một lỗ hổng critical làm lộ dữ liệu cá nhân trong phần mềm y tế mà các model trước bỏ sót.

Safeguard trước khi mở rộng

  • Theo dõi activation bên trong model để phát hiện lạm dụng (cyber, CBRN). Đã qua red team nội bộ và bên ngoài.
  • Google nói đây là model chống indirect prompt injection tốt nhất của họ, dẫn đầu benchmark IPI của Gray Swan.
  • Có hệ thống giám sát chain-of-thought và hành động để dừng agent khi nó vượt ý định người dùng. Google kêu gọi cả ngành giữ reasoning minh bạch.
👉 Vì sao quan trọng: Output 1M token kèm điểm DeepSWE cao cho thấy Argon nhắm thẳng vào agent coding chạy dài, tức mảng Claude Opus và GPT-6 đang dẫn. Ở giá mở màn, cached input chỉ còn $0,10/1M, rất có lợi cho session agent dùng nhiều context.
✅ Nên làm: Chưa dùng được ngay. Khi Argon có trên paid API, chạy thử 1–2 tác vụ refactor/migrate thật để so với model đang dùng. Ghi nhớ mốc giá tăng gấp đôi sau thời gian khuyến mãi.

#2 🔴 Phải đọc · 🛍 Shopify · — · ⭐⭐⭐

App discount dùng Shopify Functions đăng ký được intent shopify/Discount: Sidekick mở thẳng luồng tạo/sửa discount của app Mới

Hôm qua Shopify cho Sidekick gọi app intent mà không cần tools. Hôm nay mở tiếp cho discount: app tạo loại discount mới bằng Shopify Functions có thể đăng ký intent shopify/Discount. Khi merchant nhờ Sidekick tạo hoặc sửa discount, Sidekick đưa họ vào đúng luồng chuyên biệt của app thay vì UI discount mặc định của Shopify. App cũng được hiển thị trong disambiguation picker.

Áp dụng choApp tạo discount type mới bằng Shopify Functions
Action hỗ trợcreate và edit
Targetadmin.app.intent.link (trang React Router có sẵn) · admin.app.intent.render (UI inline, cần API 2026-04+)
Bắt buộc?Không. App cũ chạy như cũ, không cần migrate
MobileLuồng link chưa mở được edit trên Shopify mobile app, chỉ chạy trên admin web

Cách đăng ký

  • Intent dùng meta-schema shopify-intent.json và tham chiếu baseline schema shopify/discount.json.
  • matchValue trên functionId gắn mỗi intent với một implementation Function cụ thể. App có nhiều Function discount có thể đăng ký một luồng riêng cho từng cái.
  • Với luồng edit, value schema của intent mang theo GID của discount.
  • Mỗi intent tính vào giới hạn số intent của mỗi app, nên chỉ đăng ký những luồng thật sự cần.

Ba cách được Sidekick ưu tiên

  • Discounts UI extension (admin.discount-details.function-settings.render) được promote tự động, không cần khai báo gì thêm.
  • Đã có trang discount trong app React Router: đăng ký admin.app.intent.link để trỏ tới trang đó.
  • Muốn UI gọn, mở inline: đăng ký admin.app.intent.render (API 2026-04 trở lên).
  • extension.ui.paths vẫn hoạt động, nhưng Shopify khuyên chuyển sang intent để tích hợp Sidekick sâu hơn ở cả create lẫn edit.
👉 Vì sao quan trọng: App loyalty, bundle hay tiered discount thường dùng Function discount riêng. Nếu không đăng ký intent, merchant hỏi Sidekick sẽ bị dẫn về UI discount mặc định và bỏ qua app. Cũng nhớ tin hôm qua: thêm intent mà không có tools thì shopify.app.toml phải có extensions_summary, nếu không deploy sẽ fail.
✅ Nên làm: Liệt kê các Function discount của app và mỗi cái đang dùng UI nào (discounts UI extension hay trang trong app). Với trang trong app, thử đăng ký admin.app.intent.link với matchValue theo functionId trên dev store, đồng thời kiểm tra extensions_summary.

#3 🟡 Nên biết · 🤖 AI · 🔥🔥🔥 · ⭐⭐

Pi từng nói “không MCP”, nay đưa MCP vào core: tool chạy trong sandbox JavaScript (Codemode) thay vì nhồi schema vào context

Pi là coding harness nhỏ của Earendil, từng nổi tiếng vì tuyên bố không hỗ trợ MCP. Bản mới đưa MCP vào core. Bài viết giải thích vì sao đổi ý: vấn đề nằm ở cách harness dùng MCP, không phải ở bản thân MCP. Lời giải là chạy tool MCP trong một sandbox JavaScript gọi là Codemode. Bài đạt 615 điểm trên HN.

Thay đổiMCP vào core của Pi (trước đây chỉ là extension)
CodemodeSandbox JS chạy phía harness, agent viết JS để phối hợp nhiều tool call
Kích hoạtCodemode tự bật khi cấu hình MCP, hoặc thêm làm default tool
HN615 điểm, 341 bình luận

Vấn đề cũ của MCP

  • MCP khó compose. Nhiều server vẫn viết cho kiểu harness đổ hết tool vào context, và tối ưu token bằng cách trả về text thay vì dữ liệu có cấu trúc.
  • Quan điểm của Earendil: MCP nên gần với OpenAPI có intelligent tool discovery, tức tool trả structured data và được tìm qua tài liệu/mô tả.
  • CLI hiệu quả vì agent tự nối các lệnh bằng bash. Không có lý do gì MCP không làm được điều đó nếu tool được expose vào một sandbox JS, như cách Codex đang làm.

Codemode hoạt động thế nào

  • Harness có hai phía: nơi bash chạy (sandbox, ít tin cậy) và nơi vòng lặp agent chạy (tin cậy hơn). Codemode chạy ở phía harness.
  • Agent viết JavaScript để quyết định thứ tự gọi tool và kết hợp kết quả. State nằm trong transcript của session chứ không trên file system.
  • Chọn JS vì có thể ship bản JS thu nhỏ dưới dạng WASM, cách ly khá tốt.
  • Pi phải bổ sung metadata để cấu hình từng tool: deferred (nạp khi cần) hay chỉ dùng trong Codemode, tận dụng tính năng deferred tool loading của model mới.
👉 Vì sao quan trọng: Cùng hướng với chuyện MCP đang thành 'thuế token': nạp schema của hàng trăm tool ngay đầu session rất tốn context. Ai cấu hình nhiều MCP server cho Claude Code/Codex nên theo dõi xu hướng tool search, deferred loading và Codemode.
✅ Nên làm: Rà lại các MCP server đang bật mặc định trong harness. Chỉ bật theo project hoặc task, và ưu tiên server trả dữ liệu có cấu trúc.

#4 🟡 Nên biết · 🛠 Developer · — · ⭐⭐

Cloudflare Workers Issues: tự gom lỗi production và gửi stack trace, log, trace cho Claude Code/Cursor/Devin để mở PR Mới

Coding agent đã đọc được log, sửa code và mở PR, nhưng việc nhận ra hàng nghìn lỗi rời rạc là cùng một bug, gom context rồi chuyển cho agent vẫn đang làm tay. Cloudflare ra Issues (open beta), tính năng error monitoring tích hợp sẵn trong runtime Workers, để tự động hoá đúng khâu này.

Trạng tháiOpen beta
Bậtobservability.issues.enabled = true trong wrangler.jsonc, không cần SDK
Ghi nhậnUncaught exception, invocation fail, HTTP 5xx, console.error/log, log có stack trace
Agent hỗ trợ sẵnClaude Code (routine ID + token), Cursor (webhook), Devin (API token); hoặc webhook tuỳ ý

Cơ chế

  • Gom các exception, 5xx và error log lặp lại thành một issue, kèm thời điểm xuất hiện đầu tiên, số lần xảy ra và xu hướng tăng/giảm.
  • Phát hiện thêm vòng lặp alarm chạy mất kiểm soát và code ghi log khối lượng lớn bên trong vòng lặp.
  • Automation chạy khi issue vượt ngưỡng số lần xảy ra hoặc quay lại sau một thời gian im. Payload gồm lỗi, stack trace đã source-map, log/trace trước và sau, Worker version và context ứng dụng.

Thêm context cho agent

  • Dùng OpenTelemetry API có sẵn trong runtime để gắn user.id, account.id, session.id vào span. Nhờ đó biết lỗi có tập trung ở một tài khoản nào không trước khi giao cho agent.
  • Agent có thể nối thêm Cloudflare MCP để tự truy vấn log/trace liên quan, đề xuất sửa code và test, rồi mở PR. Người vẫn review PR, deploy và đánh dấu resolved.
  • Dùng nội bộ: trong một ngày, team Workflows tìm ra hai bug là migration kẹt trong vòng retry vì lỗi foreign key SQLite, và luồng xoá instance vượt giới hạn subrequest nên không bao giờ xong.
Gắn context người dùng vào span (Workers)
import { tracing } from "cloudflare:workers";
export default {
  async fetch(request: Request): Promise<Response> {
    const { userId, accountId, sessionId } = await getAuthDetails(request);
    const span = tracing.getActiveSpan();
    span?.setAttribute("user.id", userId);
    span?.setAttribute("account.id", accountId);
    span?.setAttribute("session.id", sessionId);
    return handleRequest(request);
  },
} satisfies ExportedHandler;
👉 Vì sao quan trọng: Đây là quy trình 'lỗi production → agent điều tra → PR' mà team nào cũng có thể tự dựng: gom lỗi theo fingerprint, đính kèm shopId/tenant làm context, rồi gửi cho Claude Code. Dù không chạy trên Workers, thiết kế này vẫn đáng tham khảo.
✅ Nên làm: Với backend app Shopify: xem log lỗi hiện có đã gắn shopId/tenant và gom được theo fingerprint chưa. Đó là điều kiện để sau này tự động giao issue cho coding agent.

AI Gateway Auto Router: tự chọn model theo độ khó, tiết kiệm tới 30% và tính cả chi phí mất cache khi đổi model Mới

Trong Claude Code, Codex hay OpenCode, người dùng thường tự chọn model và hay dùng model quá mạnh cho việc đơn giản, chẳng hạn dùng Opus để tóm tắt email. Cloudflare ra Auto Router (public beta) trong AI Gateway: mỗi request được tự động chuyển sang model vừa đủ năng lực cho tác vụ đó.

Cách dùngĐặt model = cloudflare/auto
Tiết kiệm nội bộTới 30% so với chỉ dùng frontier model (qua OpenCode)
Benchmark97 task × 3 mẫu: chất lượng tương đương, chi phí bằng 80% GPT-6 Sol và 35% Opus 5.5
GiáMiễn phí trong beta

Cách router quyết định

  • Lọc pool model theo định dạng request, credential, billing, access policy, spend limit, và loại provider đang có sự cố.
  • Một classifier multi-head chạy trên Workers AI xem các lượt hội thoại gần nhất, gán xác suất cho 14 loại task và chấm 4 chiều theo thang 1–5: complexity, ambiguity, stakes, mức phụ thuộc context trước đó.
  • Một ma trận điểm kết hợp các tín hiệu đó với benchmark của từng model. Công thức: utility = expected quality − adaptive cost penalty. Task càng khó thì trọng số giá càng thấp.

Bài học về chi phí agent

  • Session agent dài tốn tiền chủ yếu ở cache read chứ không ở giá niêm yết. Đổi model làm mất cache, model mới phải ghi lại toàn bộ context.
  • Vì vậy router gần như không đổi model trong cùng một lượt. Giữa các lượt, phạt đổi model tăng theo số token đã có trong context. Đổi model còn làm mất reasoning token mà model mới phải tính lại.
  • Model rẻ trên giấy có thể đắt hơn khi chạy thật vì tốn nhiều token hơn. Router tối ưu chi phí dự đoán của cả quá trình chứ không chỉ $/1M token.
👉 Vì sao quan trọng: Dù không dùng Cloudflare, nguyên tắc vẫn áp dụng được: khi tự định tuyến model cho tính năng AI trong app hoặc agent nội bộ, đừng đổi model giữa session dài và hãy đo chi phí của cả quá trình.

Flow Trigger Lifecycle Callback nhận URL tương đối: test local qua tunnel không phải sửa URL nữa Mới

Trước đây URL của Flow Trigger Lifecycle Callback extension bắt buộc là HTTPS tuyệt đối trỏ tới server đã host. Muốn test local phải có server sẵn, và mỗi lần URL tunnel đổi lại phải sửa cả URL này lẫn application_url. Giờ extension nhận thêm đường dẫn tương đối.

Khi app devURL tương đối ghép với tunnel URL dev
Khi app deployURL tương đối ghép với application_url của app
Không hỗ trợURL protocol-relative (//example.com/api/execute)
Điều kiện deployApp config phải có application_url HTTPS

Khi nào dùng loại URL nào

  • URL tương đối: endpoint nằm trong chính app, muốn chạy được ở cả dev và production mà không đổi config.
  • URL HTTPS tuyệt đối: endpoint host ngoài app, hoặc muốn Flow gọi cùng một URL ở mọi môi trường.
  • Cơ chế giống URL tương đối của Flow action extension, có thể dùng chung một cách cấu hình.
👉 Vì sao quan trọng: App có Flow trigger (ví dụ sự kiện điểm thưởng, đổi tier) sẽ test local nhanh hơn và bớt lỗi quên đổi URL khi chuyển môi trường.
✅ Nên làm: Nếu app có Flow trigger lifecycle callback đang hardcode URL tuyệt đối trỏ vào chính app: đổi sang path tương đối và chạy shopify app dev để kiểm tra.

“The AI Race Just Got Awkward”: giá cache-read của Opus 5.5 và GPT-6.1 Sol giảm mạnh, tác giả cho rằng nhờ tối ưu KV cache của DeepSeek Đọc sâu

DoorDash xây Agent Gateway: vì sao chỉ có MCP thì chưa đủ cho agent dùng ở quy mô doanh nghiệp Đọc sâu

MCP giải quyết việc mô tả và gọi tool (tools/list, tools/call), nhưng không trả lời agent nào được dùng tool nào, hành động chạy bằng tài khoản của ai và giám sát ra sao. DoorDash gom các câu hỏi này vào một Agent Gateway dùng chung. ByteByteGo phân tích thiết kế đó.

3 mối quan tâmAccess · Tool-surface curation · Operations
Proxy (data plane)Xác thực, kiểm quyền, rate limit, gắn credential, forward, ghi audit
Registry (control plane)Agent, MCP server, owner, auth mode, policy, catalog tool

Phân quyền chi tiết

  • Quyền không xét ở mức cả MCP server mà theo từng tool, kết hợp agent, user, tool và môi trường. Tool chỉ đọc và tool thay đổi dữ liệu được tách riêng.
  • Identity của người gọi đi theo request tới tận routing và log, nên mọi hành động downstream đều truy được nguồn. Quyết định bảo mật không nằm trong prompt.
  • Proxy cho luồng nội bộ và luồng hướng ra ngoài được tách thành các plane riêng, dùng chung thư viện nhưng mỗi plane có trust boundary riêng.

Bốn kiểu credential

  • Internal service identity: chuyển tiếp context người gọi đã xác thực tới service nội bộ.
  • Gateway-held token: token vendor lưu trong secret store của gateway, gắn vào request, agent không bao giờ thấy.
  • Per-user OAuth: gateway lưu grant của từng user, cấp token và tự refresh. Service principal: identity của team hoặc automation, dùng credential ngắn hạn.
👉 Vì sao quan trọng: Các lỗi kinh điển như agent cầm thẳng API key, đọc/ghi lẫn lộn hay không truy được ai làm gì đều được giải quyết ở tầng gateway. Đáng đọc nếu đang cho agent truy cập hệ thống nội bộ.
